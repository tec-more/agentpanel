# 端口切换：9998 / 9999 / 9100（宿主机进程 → 容器）

- 日期：2026-11-08
- 目标：宿主机三进程让位，容器接管 `127.0.0.1:9998`（L2）、`127.0.0.1:9999`（网关）、`127.0.0.1:9100`（编排）；客户端地址不变。
- 原则：先停后起，逐端口确认释放；任一步失败立即回滚。回滚有两条路径，命令均在本机实测过。

## 2. 回滚手册（两条路径）

### 2.1 回滚 A：回到容器（旧端口 19998/19999/19100）

适用：切换后容器异常，需要恢复“宿主机进程 + 容器旧端口”共存态。

```powershell
$ROOT = 'd:\programs\fastapi\agentpanel'
Set-Location $ROOT

# 1) 先停容器，避免与宿主机 9998/9999/9100 抢端口（若宿主机进程已停，可直接到第 3 步）
docker compose -f deploy/l3/docker-compose.yml --env-file deploy/l3/.env down

# 2) 还原 compose 端口（切换改动未提交时）
git checkout -- deploy/l3/docker-compose.yml
# 若切换改动已提交：git show e63b7a6:deploy/l3/docker-compose.yml > deploy/l3/docker-compose.yml

# 3) 容器回到旧端口
docker compose -f deploy/l3/docker-compose.yml --env-file deploy/l3/.env up -d
# 4) 宿主机三进程按 §2.2 的 Start 段恢复（可选：与容器旧端口共存）
```

验收：`127.0.0.1:19998/health/health`、`19999/health`、`19100/health/orchestration` 均 200。

### 2.2 回滚 B：回到宿主机进程（9998/9999/9100）

适用：容器接管失败，恢复切换前“三进程独占 9998/9999/9100”的状态。

```powershell
$ROOT = 'd:\programs\fastapi\agentpanel'
$PY   = "$ROOT\.venv\Scripts\python.exe"   # 必须用 .venv：pyenv 解释器缺 redis 模块
$CFG  = "$ROOT\config.conf"
Set-Location $ROOT

# 1) 停容器，释放 9998/9999/9100（若容器已占）
docker compose -f deploy/l3/docker-compose.yml --env-file deploy/l3/.env down

# 2) 停宿主机上任何仍占用 9998/9999/9100 的进程（含父进程，避免 venv/pyenv 启动器残留）
foreach ($p in 9998,9999,9100) {
  $pids = Get-NetTCPConnection -State Listen -LocalPort $p -ErrorAction SilentlyContinue |
          Select-Object -ExpandProperty OwningProcess -Unique
  foreach ($id in $pids) {
    $proc = Get-CimInstance Win32_Process -Filter "ProcessId=$id"
    if ($proc) { Stop-Process -Id $proc.ParentProcessId -Force -ErrorAction SilentlyContinue }
    Stop-Process -Id $id -Force -ErrorAction SilentlyContinue
    "stopped PID $id (port $p)"
  }
}
Start-Sleep -Seconds 3
foreach ($p in 9998,9999,9100) {
  $c = Get-NetTCPConnection -State Listen -LocalPort $p -ErrorAction SilentlyContinue
  "{0} => {1}" -f $p, $(if ($c) { 'STILL LISTENING' } else { 'free' })
}
# 预期：9998/9999/9100 全部 free

# 3) 从 config.conf 注入 DB/Redis 连接变量（仅子进程继承，不写系统环境）
$j = & $PY -c "import configparser,json;c=configparser.ConfigParser();c.read(r'$CFG',encoding='utf-8');print(json.dumps({'db':dict(c['db']),'redis':dict(c['redis'])}))" | ConvertFrom-Json
$env:DB_HOST=$j.db.db_host; $env:DB_PORT=$j.db.db_port; $env:DB_NAME=$j.db.db_name
$env:DB_USER=$j.db.db_user; $env:DB_PASSWORD=$j.db.db_password
$env:REDIS_ENABLED='true'; $env:REDIS_HOST=$j.redis.host; $env:REDIS_PORT=$j.redis.port
$env:REDIS_PASSWORD=$j.redis.password
$env:ORCHESTRATION_SERVICE_SECRET=[Environment]::GetEnvironmentVariable('ORCHESTRATION_SERVICE_SECRET','User')

# 4) 启动三进程（后台，日志落 logs\）
New-Item -ItemType Directory -Force "$ROOT\logs" | Out-Null
$env:UVICORN_PORT='9998'
Start-Process $PY -ArgumentList 'run.py' -WorkingDirectory $ROOT -WindowStyle Hidden `
  -RedirectStandardOutput "$ROOT\logs\host-l2.out.log" -RedirectStandardError "$ROOT\logs\host-l2.err.log"
$env:GW_PORT='9999'; $env:GW_HOST='127.0.0.1'
Start-Process $PY -ArgumentList 'services\gateway\run.py' -WorkingDirectory $ROOT -WindowStyle Hidden `
  -RedirectStandardOutput "$ROOT\logs\host-gw.out.log" -RedirectStandardError "$ROOT\logs\host-gw.err.log"
$env:ORCH_PORT='9100'; $env:ORCH_HOST='127.0.0.1'
Start-Process $PY -ArgumentList 'services\orchestration\run.py' -WorkingDirectory $ROOT -WindowStyle Hidden `
  -RedirectStandardOutput "$ROOT\logs\host-orch.out.log" -RedirectStandardError "$ROOT\logs\host-orch.err.log"

# 5) 等健康
Start-Sleep -Seconds 20
foreach ($p in 9998,9999,9100) { "== $p =="; Get-NetTCPConnection -State Listen -LocalPort $p | Select-Object LocalPort,OwningProcess }
```

验收：三个 health 均 200，`9998/api/v1/harness/runs/nope` 返回编排 401（非 503）。

> 本机实测补充：`Start-Process` 启动的进程会随 Trae 终端命令会话结束被 IDE 回收（实测端口立刻消失）。在本机回滚时，把上面第 4 段的三条命令分别作为**常驻后台任务**运行即可（等价于切换前 P3 的运行方式）；普通桌面 PowerShell 会话中 `Start-Process` 可直接使用。

> 注意：`ORCHESTRATION_SERVICE_SECRET` 必须存在（User 级，长度 52）；缺失时编排启动自检失败，内部额度接口全部 401。

## 3. 切换步骤（执行顺序）

1. 停宿主机 9998/9999/9100（按端口定位 PID，连父进程一起停）。
2. 逐端口确认释放（9998 free → 9999 free → 9100 free，每个都单独确认）。
3. `docker compose ... up -d` 重建三容器，占用 9998/9999/9100。
4. 等三容器 healthy，再做 §4 的全部验证。
